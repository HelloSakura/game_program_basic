## 智能指针

指针指针，可以自动管理内存，实际上只是raw pointer的包装


### unique_ptr

域内自动管理，离开作用域自动回收
不能copy，底层实际上是将拷贝构造函数、赋值函数设置为delete


### shared_ptr

具体实现会随着编译器变化，底层机制是引用计数


### weak_ptr

来自shared_ptr的拷贝和复制不会增加引用计数

4.返回对象中包含不同类型，使用std::tuple

## 模板template

模板比其它语言（泛型）要牛逼的多
模板有点像宏，黑科技多，但是泛型非常受制于类型系统
解释：模板允许定义一个根据用途进行编译的模板（让编译器基于某套规则生成代码），简单来讲创造一个blueprint
如果发生了实际调用才会生成对应实际参数的代码（这个地方check由编译器决定）
**编译时会根据实际调用生成对应的代码**
meta programming元编程，编译器在编译时实际在进行编程

### 关于使用
不要一棒子打死，实际上还是很好用的
在日志系统或某种其它的使用场景下，比较好用
模板搞得太复杂，不知道在干嘛

```C++
template<typename T>
void print(T value) {
    cout << value << endl;
}
print(1);
print<string>("hello");

//可以使用具体的类型，本质还是在编译期实际调用时的替换生成
template<typename T, int N>
class Array{
    T arr[N];
}
Array<5> a;
```

## 计时

chrono库 一个高效的C++ 时间库
一个timer例子
```C++
#include <chrono>
//使用C++对象生存周期和chrono库来做一个定时器
struct Timer
{
    std::chrono::time_point<std::chrono::high_resolution_clock> start, end;
    std::chrono::duration<float> duration;
    
    Timer(){
        start = std::chrono::high_resolution_clock::now();
    }

    ~Timer(){
        end = std::chrono::high_resolution_clock::now();
        duration = end - start;
        std<<cout <<"Timer: " <<duration.count() <<'\n';
    }
}

Function(){
    Timer timer;
    // do something
}

```

## 类型双关

将拥有的内存，当作不同类型的内存来对待
绕过C++类型系统，虽然类型是由编译器强制执行的，但是可以直接访问内存
```C++
//double 8bytes，int 4bytes
//大小不同，这样的转换及之后的赋值不安全
int a = 5;
double b = *(double*)&a;


//更实际的例子
struct Entity{
    int x, y;
    int* getPos(){
        //常规做法
        int *array = new int[2];
        array[0] = x;
        array[1] = y;
        return array;

        //性能优化
        return &x;
    }
}

Entity e = {5, 10};
//实际上Entity在内存之中的布局可视作一个int数组
int* pos = (int*)&e;
pos[0] = 10;   //e.x
int y = *(int *)((char*)&e + 4);    //int y = e.y;   
// 了解了内存布局和C++对于内存的访问规则，都是一样的事情
// 按照我想的方式，将内存中的数据取出来，按照想要的方式进行组织

```


## 联合体

一个联合体只能有一个成员，不同变量共用同一块内存
做的事情，通常与类型双关
匿名union不能有成员函数
```C++
struct Vector2{
    int x, y;
}

struct Vector4{
    union{
        struct{
            int x, y, z, w;
        };
        struct{
            Vector2 a, b;
        }
    }
}

Vector4 v = {1, 2, 3, 4};
v.x = 5;
v.a.x = 5;
```


## 类型转换

C++强类型语言，不能改变类型的使用，除非存在某种转换
隐式转换、显示转换

C++转换，实际上是加了点语法糖，有些情况做了点额外事情
static_cast：编译时检查，做类型转换
reinterpret_cast：把内存重新解释成别的东西（类似于类型双关）
const_cast：移除或添加变量的const限定
dynamic_cast：运行时检查，类型转换是否成功
建议使用C++风格，使代码更可靠，对他人友好

```C++
//C语言风格
double value = 5.25;
int a = (int)value;

//C++风格
int b = static_cast<int>(value);

```

### dynamic_cast

作为一种安全机制提供，做特定类型的转换，内部做了一些验证以保证转换是有效的
可以用作检查类型
dynamic_cast需要有虚函数表支持
能进行类型区分，实际上是因为存储了运行时类型信息(RTTI)
```C++
class Entity{
public:
    virtual void Print(){}
}
class Player : public Entity{}
class Enemy : public Entity{}

//隐式转换很容易
Entity* e = new Player();
Entity* e1 = new Enemy();
//向下转换很难
Player* p = e;  //error， e可能是个enemy
//需要向编译器保证e是一个player
Player* p1 = (Player*)e1;  //实际上这种操作很危险，因为e可能是enemy

Player* p2 = dynamic_cast<Player*>(e1);
if(dynamic_cast<Player*>(e1)){
    //类似于java中的 A instanceof Class
}
```

## 结构化绑定

C++17新特性，更好处理多返回值的方式

用struct:可能只有一个地方用到了定义，处理某个返回值的时候（这种实在是没必要）
如无必要，勿增实体

```C++
tuple<string, int> createPerson(){ 
    return {"hello", 5};
}

//旧方法
tuple<string, int> person = createPerson();
auto name = get<0>(person);
auto age = get<1>(person);

string name;
int age;
tie(name, age) = createPerson();

//使用struct

//C++ 17 结构化绑定
auto [name, age] = createPerson();
```

## optional数据

处理一个非期待的返回值，处理可能存在、可能不存在的情况；
```C++
//普通版本
std::string readFile(const std::string& path, bool& isSucceed)
{
    std::ifstream file(path);
    if(file){
        std::string res;
        //read file
        file.close();
        isSucceed = true;
        return res;
    }
    isSucceed = false;
    return std::string();
}

bool isOpenSucceed;
auto data = readFile("file.txt", isOpenSucceed);
if(isOpenSucceed){ 
    //do something
}


//optional版本
std::optional<std::string>readFile(const std::string& path)
{
    std::ifstream file(path);
    if(file){
        std::string res;
        //read file
        file.close();
        return res;
    }
    return {};
}


auto data = readFile("file.txt");
std::string value = data.value_or("not_present");
if(data.has_value()){       //这里的处理比较好
    //do something
}

```

## 左值和右值

左值：有地址的值，int i = 10，**左值是有某种存储支持的变量**
右值：10，字面量，临时变量，**右值是临时值**
左值引用：int& a = i，**左值引用只接受左值，除非用const(会隐式进行一次转换)**
右值引用：int&& a = 10，个人理解是对临时变量的引用，**仅接受右值**
不能将右值赋给左值引用，左值引用只能绑定左值

为什么重要：

右值引用带来的操作：主要用于优化，如果知道传入的是一个右值，就不需要担心其内部的内容和管理（存活、完整、拷贝。。。）
可以简单将其资源给到特定的对象或者其它地方

```C++
int a = 5;
int& b = a;
int& c = 5; //error，不能用左值来引用右值
const int& d = 5;   //ok

//const int& 兼容临时的右值和实际存在的左值变量
void print(const int& value)
{
    //能兼容的原因是做了一次转换
    //右值先隐式转换成了一个临时左值
}

//只使用左值引用版本
void print(int& value){}
print(a);   //ok
print(5);   //error

//右值引用版本，只接受临时变量
void print(int&& value){}
```


## 参数求值顺序

没有提供一个规范，参数应该按照什么顺序求值（可能会出现 0+0 =0 的情况，由于编译器优化）
C++17 加了个新标准，后缀表达式必须在别的表达式之前被计算（两件事不能同时做）


```C++
void printSum(int a, int b)
{
    std::cout << a << "+" << b << "=" << (a+b) << std::endl;
}

int v = 0;
printSum(v++, v++); //实际上这是未定义行为，取决于编译器实现
```

## 移动语义

可以干嘛？
本质上允许移动对象（C++11引入了右值引用，右值引用允许移动对象这种操作）
场景：
大多数情况下不需要复制一个对象，但是又不得不复制（譬如参数传递和返回值）
支持移动语义，需要提供右值引用版本的构造函数和赋值运算符
C++五法则：如果需要析构函数，则一定需要拷贝构造函数和拷贝赋值函数；如果要支持移动语义，需要移动构造函数和移动赋值函数


```C++
class Entity{
public:
    //右值引用版本
    Entity(Entity&& entity) noexcept
    {
        //move的语义是不构造新的内存，交换内存
        //对应的原有的内存要置为nullptr
        m_size = entity.m_size;
        m_data = entity.m_data;
        entity.m_size = 0;
        entity.m_data = nullptr;
    }
    //赋值版本
    Entity& operator=(Entity&& entity) noexcept
    {
        if(this == &entity) return *this;   //不和自身交换
        delete[] m_data;    //需要先释放自己的内存，准备交互变量内存
        m_size = entity.m_size;
        m_data = entity.m_data;
        entity.m_size = 0;
        entity.m_data = nullptr;
    }

private:
    int m_size;
    char* m_data;
}

Entity a = new Entity();
Entity b = std::move(a);    //使用移动构造函数，Entity b构造了一个新的对象

Entity c;
c = std::move(b);   //使用移动赋值函数

```
