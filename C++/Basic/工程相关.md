## 库文件
### 静态库
静态链接是编译时进行链接
链接二进制文件，库通常文件结构包含两部分，includes和library，包含目录和库目录
对于VS，包含头文件，将链接器指向库文件（先将将头文件和库文件拷贝到对应目录）
1.指定链接库的文件路径；
2.相对于库目录的库文件名称；


### 动态库
动态链接是运行时进行链接
确保有一个可访问的dll文件，同样需要配置编译器的动态库路径
关于动态库的位置：
1.直接放在exe目录下；
2.放在系统目录下；

## 命名空间

为什么不使用using namespace std
>1. 可以直观看出引用是来自标准库
>2. 避免不同标准库中的同名函数导致的运行时错误

当存在两个相同的符号时，会产生编译错误
C语言没有命名空间，会将库的实际名称或某种id嵌入到函数名中（譬如OpenGL,glCreateShader）
C++使用命名空间来避免命名冲突，能够在不同的上下文中使用相同的名称
可以给命名空间起别名，简化嵌套命名空间时的字符长度

## 预编译头文件

实际是赚取一堆头文件，并将其转换成编译器可以使用的格式，可以直接使用，而不是一遍一遍的读取
简单例子来讲，main中包含了vector，vector需要其它文件
#include又是复制粘贴的机制，那么每次#include<vector>会带来大量的解析工作，在编译main文件之前；
每次对文件的修改都会重新解析编译 => 潜在编译时长变长

预编译头文件：接受一堆头文件，只编译一次，以二进制存储，下次编译时直接使用，减少编译时长，譬如vector，引入后不需要重新解析，只需要看预编译的头文件
**如果关心编译时间，一定要使用预编译头文件**
**使用pch会隐藏外部依赖，因为不需要#include指明要包含的引用文件**
**决定是否放入pch，考虑文件的使用频率，代码可读性**
不要把经常变化的东西塞进预编译头文件，这样每次修改都会重新编译
主要是用于C++库、模板库、API上的代码，不是自己写的；

VS使用预编译文件需要进行设置

```C++
//pch.cpp
#include "pch.h"

//pch.h
#pragma once
#include <iostream>
#include <algorithm>

//data struct
#include <string>
#include <vector>
#include <map>

//api
#include<windows.h>

```

## 单例模式

在哪里发挥作用，当想要拥有应用于某种全局数据集的功能，且我们只是想要重复使用时，单例非常有用
C++中的单例只是一种组织一堆全局变量和静态函数的方式

```C++
class Singleton {

private:
    Singleton() {}  // 私有构造函数

public:
    static Singleton& getInstance() 
    {
        static Singleton s_instance;
        return s_instance;
    }

    Singleton(const Singleton&) = delete;   // 禁止拷贝构造
    //将成员方法转成类方法，简化写法
    static int doSomething() { return getInstance().IDoSomething(); }

private:
    int IDoSomething() {}
}

auto a = Singleton::doSomething();
```
